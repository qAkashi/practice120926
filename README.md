# CRM: партнёры и скидки

Учебный проект на Python, Tkinter и PostgreSQL. Список партнёров, расчёт скидок,
добавление и редактирование карточек, история отгрузок, валидация и системные уведомления.

## Быстрый запуск в VS Code

1. Откройте **всю папку hexlet**: Файл → Открыть папку.
2. Нажмите Ctrl+Shift+P → **Python: Select Interpreter** и выберите
   `hexlet/.venv/Scripts/python.exe`. После переноса не выбирайте окружение старой папки 21_09_26.
3. Откройте `run_app.py` **в корне hexlet** и нажмите **Run Python File** (треугольник).
   Также настроен запуск F5: «CRM — итоговое приложение».
4. В окне подключения введите пароль пользователя PostgreSQL, который используете в pgAdmin.
   Пароль в репозитории не хранится.

Корневые run_app.py и run_tests.py автоматически используют Python из `.venv` проекта,
если это окружение существует. Это защищает обычный запуск от устаревшего выбора
интерпретатора в VS Code. Для отладки F5 всё равно выберите интерпретатор проекта.

Если проект только что скачан с GitHub: установите Python с Tcl/Tk и расширение Python для VS Code,
затем Ctrl+Shift+P → **Python: Create Environment** → **Venv** → выберите Python
и корневой `requirements.txt` для установки зависимостей. Виртуальные окружения в Git не входят.
Проверенная среда: Windows, Python 3.14, PostgreSQL 18, Psycopg 3, pytest, coverage.

## Подключение и подготовка базы

Настройки итогового приложения: [database.ini](<Учебная практика/Учебная практика 21.09.2026/Интеграция формы с БД (CRUD-операции и обновление UI)/database.ini>).

По умолчанию: localhost, порт 5432, база partner_shipments, пользователь postgres.
Перед запуском должна работать служба PostgreSQL.

### Если база уже существует

Перенос файлов не переносит и не очищает PostgreSQL. Если CRUD из предыдущего этапа уже работал,
достаточно проверить database.ini и запустить приложение. Если новые столбцы ещё не добавлены,
в pgAdmin выберите именно partner_shipments → Query Tool → откройте следующий файл → F5:

- [migrate_partner_card.sql](<Учебная практика/Учебная практика 21.09.2026/Интеграция формы с БД (CRUD-операции и обновление UI)/migrate_partner_card.sql>)

Миграция сохраняет партнёров и отгрузки. Повторно запускать schema.sql на заполненной БД не нужно: он содержит DROP TABLE.

### Если базы ещё нет

В pgAdmin создайте базу partner_shipments и выполните через Query Tool по порядку:

1. [Создание исходной схемы — schema.sql](<Учебная практика/Учебная практика 07.09.2026/Написание DDL-скрипта (База данных в коде)/schema.sql>).
2. [Импорт исходных подготовленных данных — data.sql](<Учебная практика/Учебная практика 07.09.2026/Подготовка данных и импорт (ETL)/data.sql>).
3. [Проверки импорта — checks.sql](<Учебная практика/Учебная практика 07.09.2026/Подготовка данных и импорт (ETL)/checks.sql>).
4. [Расширение карточки — migrate_partner_card.sql](<Учебная практика/Учебная практика 21.09.2026/Интеграция формы с БД (CRUD-операции и обновление UI)/migrate_partner_card.sql>).

Используйте data.sql один раз на пустых таблицах. import.sql — альтернативный способ для psql,
его команды \copy не предназначены для обычного Query Tool. Наименование, email и ИНН должны
соответствовать ограничениям; старые дробные рейтинги миграция не округляет.
При редактировании такой карточки укажите целое неотрицательное значение.

## Проверка приложения

1. Посмотрите список и скидки: у партнёра без продаж должно быть 0%.
2. Нажмите «Добавить партнера», заполните поля и сохраните. После подтверждения БД список обновится.
3. Дважды щёлкните карточку: данные заново читаются из БД. Измените поле и сохраните.
4. Введите пустой email или рейтинг -1: появится Error с инструкцией, форма не закроется.
5. Измените поле и нажмите «Назад»: Warning позволяет вернуться к форме или отказаться от изменений.
6. После успешной записи появится Information. При редактировании ID и отгрузки сохраняются.
7. Выберите карточку одним щелчком и нажмите «История продаж». Откроются товары, количество
   и даты отгрузок выбранного партнёра за весь период. Кнопка «Назад» сохраняет поиск и прокрутку.
8. У нового партнёра без продаж появится сообщение «У этого партнёра пока нет отгрузок».

Для истории используются существующие таблицы deliveries, delivery_items и products.
Дополнительная миграция после работающей версии 21.09 не нужна.

Расчёт сырья выполняется по формуле из задания с округлением вверх. Для проверки запустите
manual_check.py в [папке расчёта сырья](<Учебная практика/Учебная практика 28.09.2026/Разработка ядра алгоритма расчета материалов/README.md>).
Он использует учебные мок-справочники, поэтому PostgreSQL не нужен. Пример ввода:
ID продукции 1, ID материала 1, количество 10, параметры 2 и 3 → результат 95.

Этот же метод доступен в приложении по кнопке **«Расчёт сырья»**.
Окно содержит пять полей и выводит результат после нажатия «Рассчитать».
При неверном вводе появляется диалог с инструкцией, а прежний результат сбрасывается.
Для проверки без входа в БД отмените окно подключения и откройте калькулятор.
Подробности и снимки экрана — в [третьем задании](<Учебная практика/Учебная практика 28.09.2026/Интеграция метода расчета и комплексное тестирование/README.md>).

Ошибки записываются в app.log внутри [четвёртого задания](<Учебная практика/Учебная практика 28.09.2026/Модульное тестирование (Unit Testing) и аудит безопасности/README.md>).
Каждая запись содержит дату, время и описание; пароли и значения полей карточек не записываются.
Файл журнала и его архивы исключены из Git. При недоступности файла ошибки выводятся в консоль.
Отчёт о проверке параметризованных запросов находится в security_audit.md в четвёртом задании.

## Тесты

Откройте корневой `run_tests.py` в VS Code и запустите Run Python File.
Введите пароль PostgreSQL в терминале; ввод скрыт. Результат проверки версии 28.09
сохранён в [test_results.txt блока](<Учебная практика/Учебная практика 28.09.2026/test_results.txt>).
Они не меняют рабочие таблицы: используются временные таблицы и отдельные схемы тестов.
Тестовому пользователю необходимо право CREATE на БД. Для CI можно задать TEST_DATABASE_DSN.
Покрытие расчёта скидки, сервиса партнёров, сервиса истории и расчёта сырья
с мок-справочниками — 100%, включая ветвления.
Это покрытие указанных модулей, а не всего интерфейса. Проверяются также навигация,
CRUD, выбор партнёра, пустая история, ошибки подключения и закрытие окна во время загрузки.

Отдельно можно запустить manual_check.py и run_tests.py в задании расчёта скидки 14.09.
Версия приложения и полный набор тестов 14.09 запускаются через run_app.py/run_tests.py в папке этого блока.
