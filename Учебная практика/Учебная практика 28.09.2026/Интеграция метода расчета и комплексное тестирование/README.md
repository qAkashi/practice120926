# Интеграция метода расчета и комплексное тестирование

Третье задание блока 28.09.2026. На главной форме появилась кнопка **«Расчёт сырья»**.
Она открывает отдельное окно с общими шрифтами, цветами, логотипом и иконкой приложения.
Окно вызывает `calculate_material_quantity` из второго задания с пятью параметрами.

Общие модули подключаются через project_paths.py. Названия двух предыдущих папок
сохранены, пути запуска и документация приведены в соответствие с ними.

## Запуск в VS Code

1. Откройте всю папку hexlet и выберите `.venv/Scripts/python.exe` как интерпретатор.
2. Запустите корневой run_app.py кнопкой **Run Python File**.
3. Подключитесь к PostgreSQL или отмените вход, если хотите проверить только калькулятор.
4. Нажмите **«Расчёт сырья»**.
5. Введите ID типа продукции `1`, ID материала `1`, количество `10`, параметры `2` и `3`.
6. Нажмите **«Рассчитать»**. На форме появится «Необходимое количество сырья: 95».

Используются учебные мок-справочники второго задания; справочные значения указаны рядом с полями.
ID можно выбрать из списка или ввести вручную. При неизвестном ID метод возвращает -1.
Дробные параметры можно вводить с точкой или запятой. Enter в поле запускает расчёт.

## Проверка ошибок

| Ввод | Ожидаемое поведение |
| --- | --- |
| Параметр 1 = -2 | Метод возвращает -1; появляется окно «Ошибка расчёта сырья» |
| ID типа продукции = 999 | Сообщение предлагает выбрать существующий ID |
| Количество = 0 или -5 | Сообщение требует целое количество больше нуля |
| Количество = 1.5 или abc | Ошибка преобразования перехватывается, программа продолжает работать |
| Пустое поле, NaN или inf | Расчёт отклоняется с объяснением |
| Исправление параметров и повторный расчёт | Диалог закрывается кнопкой OK; новый результат появляется на форме |

Диалог использует системный тип Error и соответствующую пиктограмму. Значение -1 не выводится
как количество сырья. Данные после ошибки остаются в форме для исправления.
При любом изменении поля прежний результат заменяется предложением пересчитать расход.

Кнопка «Назад», Escape и крестик возвращают к реестру с сохранением его поиска, выбора и прокрутки.
История, редактирование и калькулятор не открываются поверх друг друга.
Кнопка калькулятора не создаёт второе окно, если первое уже открыто.
Сам калькулятор ничего не записывает в базу данных.

## Проверки кода

В новом коде используются snake_case для функций, методов и переменных, одна команда на строку.
Имена классов MainWindow и MaterialWindow следуют принятому в Python стилю PascalCase.
Формула используется из готового метода. Комментарий о точном округлении оставлен рядом
с преобразованием чисел в ядре алгоритма; очевидные действия интерфейса не комментируются.

Весь блок 28.09 проверен через AST и tokenize: синтаксис, отсутствие нескольких инструкций
на одной строке и разделителей `;`, именование функций и аргументов. Результат — style_check.txt.

Запустите run_ui_tests.py из этой папки для 29 тестов интерфейса без БД.
Корневой run_tests.py запускает также тесты истории, CRUD и алгоритмов на тестовых схемах PostgreSQL.
Общий протокол — [test_results.txt блока](../test_results.txt).
