# Просмотр истории реализации продукции партнёра

Окно `PartnerHistoryWindow` показывает отгрузки выбранного партнёра за весь период.
Заголовок содержит назначение окна и актуальное название партнёра.
Используются общие ресурсы приложения: логотип, иконка, Arial, белый фон и серые кнопки.

## Файлы задания

| Файл | Назначение |
| --- | --- |
| history_main_window.py | Выбор карточки, кнопка «История продаж» и передача partner_id |
| partner_history_window.py | Окно с таблицей, обновлением и возвратом к списку |
| partner_history_service.py | Чтение истории из PostgreSQL по ID партнёра |

Запускайте приложение через [run_app.py блока](../run_app.py) или корневой run_app.py.
Общие классы и настройки подключаются через project_paths.py; файлы окна отдельно не запускаются.

## Проверка вручную

1. Запустите приложение и подключитесь к PostgreSQL.
2. Щёлкните карточку партнёра один раз: рамка выделится, кнопка «История продаж» станет доступной.
3. Нажмите кнопку. Проверьте название партнёра в заголовке и три столбца:
   «Наименование продукции», «Количество (шт.)», «Дата продажи».
4. Даты показаны как ДД.ММ.ГГГГ, новые отгрузки идут первыми.
   Для партнёра с ID 1 в исходном наборе: 30 шт. кондиционера 20.03.2026 и 50 шт. порошка 01.03.2026.
5. Нажмите «Обновить»: история повторно прочитается из БД. Длинные названия можно просмотреть
   горизонтальной прокруткой, большое число строк — вертикальной.
6. Нажмите «Назад», Escape или крестик: выбранная карточка, строка поиска и прокрутка сохранятся.
7. Откройте историю партнёра без продаж: появится пояснение, таблица останется пустой.

Двойной щелчок по карточке по-прежнему открывает редактирование.
Запрос выполняется в фоновом потоке с отдельным подключением. При недоступности БД
появится диалог с инструкцией; можно повторить загрузку кнопкой «Обновить» или вернуться назад.

## SQL и проверка данных

В `history.sql` измените значение partner_id в первой строке SELECT и выполните весь запрос
в Query Tool базы partner_shipments. JOIN связывает deliveries → delivery_items → products.
Одна строка таблицы соответствует одной позиции отгрузки, количество измеряется в штуках.

Сервис приложения передаёт ID параметром `%s`, а не вставляет его в текст SQL.
Дополнительный LEFT JOIN с partners позволяет отличить отсутствие продаж от удаления самого партнёра.
Название партнёра также читается заново при каждом открытии и обновлении истории.

## Автоматические проверки

Запуск: run_tests.py в корне репозитория или блока 28.09.
Тесты проверяют выбор по ID, JOIN нескольких товаров и дат, исключение продаж других партнёров,
пустую историю, удалённого партнёра, неверный ID, формат дат, видимость кнопок в маленьком окне,
возврат без потери состояния, повторное открытие, ошибку БД и закрытие во время загрузки.
Также выполняются проверки скидок, CRUD, валидации и диалогов предыдущего этапа.

Покрытие partner_history_service, partner_service и partner_discount — 100% строк и ветвлений.
Полный протокол проверки: [test_results.txt](test_results.txt).
