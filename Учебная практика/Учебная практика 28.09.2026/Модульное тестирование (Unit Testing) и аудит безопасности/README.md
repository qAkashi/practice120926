# Модульное тестирование (Unit Testing) и аудит безопасности

Четвёртое задание блока 28.09.2026. Файлы интерфейса калькулятора находятся отдельно,
в третьей папке «Интеграция метода расчета и комплексное тестирование».

## Выполнение задания

1. **Unit-тесты метода** — tests/test_material_requirements.py. Пять явно названных сценариев:
   стандартный результат 33; округление 94.5 вверх до 95; неизвестные ID; отрицательный первый
   или второй параметр; количество 0 или -1. С параметризацией получается восемь проверок.
2. **Аудит SQL** — [security_audit.md](security_audit.md), tests/test_sql_security.py
   и tests/test_sql_security_postgres.py. Проверяются отдельная передача параметров,
   текстовый поиск, пароль подключения и сохранение SQL-подобного текста как данных.
3. **Журнал ошибок** — app_logging.py и audit_main_window.py. Ошибки чтения и записи БД,
   ввода калькулятора, валидации карточки и обработчиков Tkinter записываются в app.log.

## Запуск и проверка в VS Code

1. Откройте весь проект hexlet и выберите интерпретатор `.venv/Scripts/python.exe`.
2. Откройте run_audit_tests.py в этой папке и нажмите **Run Python File**.
3. Без подключения к PostgreSQL выполняются 27 проверок, три интеграционных теста пропускаются.
   Для полного набора запустите корневой run_tests.py и введите пароль PostgreSQL.
   Тесты БД работают во временных схемах и не меняют рабочие таблицы.

Если VS Code выбрал другой Python, run_audit_tests.py автоматически перезапустится
через существующее окружение hexlet/.venv до импорта pytest.

Тесты нового задания используют тот же метод из второго задания. Предыдущие 57 тестов
математического ядра также сохранены и входят в общий запуск.

## Проверка лога вручную

1. Запустите корневой run_app.py.
2. Отмените вход в PostgreSQL, если проверяете только калькулятор.
3. Откройте «Расчёт сырья» и введите буквы вместо количества продукции.
4. Нажмите «Рассчитать» и закройте диалог ошибки кнопкой OK.
5. Откройте app.log в этой папке. Запись содержит дату, время, уровень ERROR,
   название операции, тип ValueError и понятное описание ошибки ввода.
6. Заполните все поля корректно, затем введите отрицательный параметр. Метод вернёт -1;
   этот отказ будет записан с уровнем WARNING. После исправления расчёт снова работает.

Журнал не содержит исходные значения полей, пароль или сырые сообщения драйвера PostgreSQL.
Вместо них записываются контролируемые описания ошибок. Ожидаемая пустая очередь UI не считается ошибкой.
Если файл невозможно открыть для записи, сообщения выводятся в консоль.
При достижении 1 МБ журнал ротируется; остаётся не более двух архивов.

app.log и app.log.* исключены из Git. Для сдачи приложен [пример реальных записей](error_log_example.txt),
полученных при демонстрационной проверке интерфейса.

| --- | --- |
