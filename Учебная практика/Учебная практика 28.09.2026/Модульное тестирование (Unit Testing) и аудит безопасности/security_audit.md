# Аудит защиты от SQL-инъекций

Проверен путь пользовательских данных в текущей версии приложения 28.09.2026:
поиск, пароль подключения PostgreSQL, карточка партнёра и история отгрузок.
Рассматривался рабочий код, а не только примеры SQL для pgAdmin.

## Проверенные участки

| Ввод / операция | Реализация | Результат |
| --- | --- | --- |
| Поиск по названию | main_window.py: render_partners из блока 21.09 | Поиск подстроки в загруженном списке Python, SQL не строится |
| Пароль подключения | database.py: connect_database из блока 21.09 | Передаётся как keyword-аргумент password в psycopg.connect; не добавляется к SQL или строке DSN |
| Создание карточки | partner_service.py: save_partner из блока 21.09 | INSERT с восемью `%s`, значения отдельным кортежем |
| Изменение карточки | Там же | UPDATE с `%s`; ID передаётся последним параметром WHERE |
| Получение карточки | get_partner_with_discount → read_partners | ID проверяется, затем передаётся параметром в cursor.execute |
| История отгрузок | partner_history_service.py: get_partner_history | Оба вхождения ID передаются отдельно: `(partner_id, partner_id)` |
| Расчёт сырья | material_calculator.py | Использует разрешённые мок-справочники, SQL отсутствует |

В read_partners используется f-строка для выбора статического фрагмента WHERE.
Её вставка — только пустая строка или константа `WHERE p.partner_id = %s`.
Пользовательский текст не интерполируется, значение ID передаётся отдельным параметром.
Это не динамическая подстановка пользовательского ввода в SQL.

## Проверки

- Проверка вызовов execute: SQL и параметры передаются раздельно при INSERT, UPDATE и SELECT.
- Передача `1 OR 1=1` в публичные методы по ID отклоняется до SQL.
- Поиск `' OR 1=1 --` остаётся обычным поиском текста и не вызывает загрузчик БД.
- SQL-подобная строка пароля остаётся одним аргументом драйвера; она не меняет dbname.
- Интеграционные тесты PostgreSQL вставляют и обновляют текст `x'); DROP TABLE partners CASCADE; --`
  в названии, адресе и ФИО директора. Значения читаются обратно как текст, таблицы сохраняются,
  данные второго партнёра не меняются.
- Повторная проверка существующих тестов CRUD подтверждает транзакционность, валидацию и связи отгрузок.

В проверенных путях SQL-инъекции не обнаружены; исправлять параметризацию запросов не потребовалось.
Не добавлено ручное экранирование кавычек: за передачу значений отвечает psycopg.

## Защита журнала

Сырые тексты исключений и аргументы операций не записываются: ошибки PostgreSQL могут содержать
контактные данные или детали подключения. Сохраняются тип исключения, операция и контролируемое
описание. Переводы строк в описаниях заменяются пробелами. Журнал и архивы исключены из Git.
Тест с искусственным паролем и email проверяет, что они не попадают в лог.

## Границы аудита

В приложении нет отдельной системы учётных записей менеджеров: окно входа запрашивает пароль
подключения к PostgreSQL. Тесты не являются проверкой конфигурации сервера, сети, прав пользователей
или всех возможных атак. Они подтверждают перечисленные свойства текущего кода.
Использована отдельная тестовая БД; реальные таблицы приложения не изменялись.
