# Разработка UI, навигации и CRUD-форм

Третье задание блока 05.10.2026. Приложение на Python/Tkinter работает с PostgreSQL
practice_051026 из первого задания. Расчёт скидки использует функцию второго задания.

При выполнении четвёртого задания в этот рабочий код добавлены пошаговые сообщения
об ошибках и защита обработчиков Tk. Аудит и общий прогон находятся в соседней папке
«Автоматизированное тестирование, аудит безопасности и UX».

## Запуск в VS Code

1. Откройте всю папку hexlet.
2. Если база ещё не подготовлена, выполните run_import.py из папки
   «Инфраструктура данных и ETL (База данных в 3NF)». Повторный импорт после
   изменения данных в интерфейсе не нужен.
3. В этой папке проверьте database.ini: localhost, порт 5432,
   база practice_051026, пользователь postgres.
4. Откройте **run_app.py именно в этой папке** и нажмите **Run Python File**.
5. В диалоге введите пароль пользователя PostgreSQL.
   Пароль хранится только в памяти приложения.
6. Дождитесь списка партнёров. Нажмите «Подключиться» для повторного подключения,
   если пароль был введён неверно.

При запуске автоматически используется .venv в корне hexlet, если она существует.
Для чистого проекта в VS Code выберите Python: Create Environment → Venv,
затем requirements.txt для установки зависимостей. Python должен включать Tkinter.

Корневой run_app.py репозитория по-прежнему запускает приложение блока 28.09.
Для нового задания используйте локальный run_app.py, указанный выше.

## Что реализовано

- **MainWindow** — реестр, поиск по названию, типу, телефону, Email и ИНН,
  контакты, рейтинг, суммарный объём и текущая скидка.
- **PartnerEditWindow** — добавление и редактирование, все семь полей из задания
  и дополнительное поле ИНН, обязательное по схеме БД.
  Тип выбирается из readonly ComboBox: ЗАО, ООО, ИП, АО, ПАО, ОАО.
  Рейтинг принимает только целое неотрицательное число в диапазоне PostgreSQL INT.
  Поля содержат плейсхолдеры и постоянные подсказки; текст плейсхолдера не сохраняется.
- **PartnerHistoryWindow** — история конкретного partner_id:
  наименование товара, дата в формате ДД.ММ.ГГГГ и количество.
  Для партнёра без продаж показывается понятное сообщение.
- В каждом окне свой заголовок, иконка и логотип. Сохранены ресурсы и стиль
  предыдущего блока: Arial, белый фон, тёмный текст, нейтральные серые кнопки.
- После успешного INSERT/UPDATE карточка закрывается и список автоматически
  перечитывается из БД. Первичный ключ при редактировании не изменяется.
- «Назад», Escape и крестик возвращают на главную форму.
  Главное окно не создаётся повторно, поэтому сохраняются поиск, выбор и прокрутка.
  Несохранённые изменения требуют подтверждения потери.
- Поиск сохраняется и после сохранения: если новое название перестало соответствовать
  фильтру, запись временно не видна. Очистите строку поиска, чтобы увидеть её.
- Запросы работают в фоновом потоке; Tk получает результаты через очередь.
  Закрытие во время чтения не приводит к обращению к уничтоженным виджетам.
  Во время сохранения повторная отправка и закрытие карточки заблокированы.
- Ошибки ввода, дубликаты ИНН/Email и проблемы подключения показываются в диалогах.
  При неудачном сохранении введённые значения остаются в карточке.

## Изменения БД

migration.sql выполняется автоматически при подключении в транзакции.
Добавляются partner_type, rating, address, director_name и phone, без удаления
исходных таблиц, партнёров и продаж. Повторный запуск безопасен для этих данных.

Тип выводится из префикса исходного названия, если он известен.
Исходное полное наименование сохраняется. Рейтинг по умолчанию — 0,
непредоставленные адрес, директор и телефон остаются пустыми.
У неизвестного типа остаётся пустое значение до выбора в форме.

Миграцию можно выполнить вручную в Query Tool базы practice_051026.
Для автоматической миграции пользователю нужны права изменения таблицы partners.
Не запускайте старые скрипты с DROP TABLE на заполненной базе.

Все пользовательские значения передаются в SQL отдельными параметрами.
INSERT/UPDATE выполняются в транзакции. История использует JOIN с products;
список — LEFT JOIN, SUM(quantity) и COALESCE. Партнёры без продаж получают 0%.

## Ручная проверка

1. Запустите приложение: должно быть пять исходных партнёров со скидкой 0%.
2. Выберите партнёра и нажмите «История продаж»: проверьте название товара,
   дату и количество. Нажмите «Назад».
3. Введите текст поиска и выберите партнёра. Откройте карточку двойным щелчком
   или кнопкой «Редактировать»: текущие данные загружаются заново из БД.
4. Измените рейтинг и телефон, сохраните. После сообщения об успехе
   список должен показать новые данные, а выбранный партнёр — остаться выбранным.
5. Нажмите «Добавить партнёра». Заполните наименование, тип, рейтинг,
   уникальные ИНН и Email. После сохранения запись появится в списке.
6. Откройте историю нового партнёра: должно быть сообщение об отсутствии продаж.
7. Попробуйте пустой Email и повторяющийся ИНН: сохранение не выполняется,
   диалог объясняет, что исправить. Минус и дробная часть в рейтинге не вводятся.
8. Измените поле и нажмите «Назад»: отказ от выхода сохраняет черновик,
   подтверждение закрывает форму без записи в БД.

## Автоматическая проверка

Откройте run_tests.py этой папки и нажмите Run Python File.
36 тестов выполняются без PostgreSQL, 8 интеграционных требуют TEST_DATABASE_DSN.
Тесты интерфейса требуют доступного графического рабочего стола с Tkinter.

Для полного прогона задайте TEST_DATABASE_DSN для тестового подключения и пароль
через PGPASSWORD или pgpass. Не сохраняйте пароль в репозитории.
Интеграционные тесты создают и удаляют только собственные схемы ui_test_<uuid>,
не изменяя рабочие таблицы public.

Проверено 11.10.2026: **44 теста прошли** на Python 3.14 / PostgreSQL 18,
включая добавление, редактирование и историю через настоящий UI с тестовой БД.
Результат сохранён в test_results.txt. Снимки окон сделаны на отдельном сервере
127.0.0.1:55439; для вашего localhost:5432 потребуется ваш пароль.
