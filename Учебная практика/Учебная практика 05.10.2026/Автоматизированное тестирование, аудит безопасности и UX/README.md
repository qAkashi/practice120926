# Автоматизированное тестирование, аудит безопасности и UX

Четвёртое задание блока 05.10.2026. Проверяется настоящее приложение из третьей
папки и алгоритмы из второй; отдельные копии рабочего кода здесь не создаются.
Исправления UX внесены в общие main_window.py, partner_edit_window.py и ui_common.py
третьего задания, поэтому работают при запуске из обеих папок.

## Что выполнено

1. Тесты метода расчёта материалов на pytest: базовый расчёт, округление вверх,
   точное целое без лишней единицы, отсутствующие типы продукции и материала,
   отрицательные и нулевые размеры, количество <= 0, неправильные типы,
   недоступность БД и 1000 повторных вызовов.
2. Аудит запросов и тесты SQL-инъекций. Все переменные значения в запросах
   приложения передаются отдельно от SQL. Поиск в главном окне выполняется
   в памяти и вообще не строит SQL. Экспорт SQL первого задания переведён
   на безопасные Identifier/Literal Psycopg.
3. Ошибки ввода и PostgreSQL показываются через showerror с пиктограммой ошибки
   и нумерованными шагами исправления. Диалоги не раскрывают сырые исключения.
4. Изменённая карточка при выходе показывает предупреждение с иконкой warning
   и текстом о потере данных без возможности восстановления. Отмена выхода
   сохраняет введённые значения.
5. Исключения в обработчиках Tk и фоновых результатов перехватываются.
   Ошибка обработчика больше не останавливает цикл получения результатов.
   Невозможность запустить фоновый поток снимает блокировку кнопок.
6. Комментарии оставлены у неочевидной логики: точное округление, savepoint,
   передача результатов из потока, обработка исключений Tk и изоляция тестов.

## Файлы

- audit_paths.py — подключение рабочих модулей соседних папок.
- tests/test_material_contract.py — контракт метода расчёта.
- tests/test_sql_security.py — параметры SQL и защита от внедрения команд.

- tests/test_ux_resilience.py — MessageBox, предупреждения и устойчивость UI.
- security_audit.md — область, результаты и ограничения аудита.
- test_results.txt — сохранённый полный прогон.
- manual_checks.md — сценарии проверки перед сдачей.

## Запуск в VS Code

Откройте **run_app.py этой папки** → **Run Python File** → введите пароль PostgreSQL.
Используются database.ini и ресурсы третьего задания. База — practice_051026.
Если она ещё не создана, сначала выполните run_import.py первого задания.

Для проверки откройте **run_tests.py этой папки** → **Run Python File**.
Существующее окружение .venv корня hexlet используется автоматически.
Запуск без TEST_DATABASE_DSN проверяет расчёты и UI, а тесты реальной БД отмечает skipped.
Тестам окон нужен графический рабочий стол с Tkinter; часть окон кратковременно создаётся.

Для полного прогона в терминале VS Code задайте подключение к тестовой БД:

```powershell
$env:TEST_DATABASE_DSN = 'host=localhost port=5432 dbname=practice_051026 user=postgres'
```

Пароль передайте через pgpass или переменную PGPASSWORD вашей локальной среды.
Не записывайте пароль в код, README или Git. Затем запустите run_tests.py.
Пользователь PostgreSQL должен иметь право CREATE: тесты используют отдельные
схемы со случайными именами и удаляют только созданные ими схемы.

В чистом проекте сначала создайте .venv через Python: Create Environment в VS Code
и установите requirements.txt. Корневой run_app.py продолжает открывать старый
блок 28.09; для этой работы используйте запуск из текущей папки.

## Результат

11.10.2026 на Python 3.14 и PostgreSQL 18 все **174 теста прошли**:

| Набор | Пройдено |
| --- | ---: |
| ETL и схема | 29 |
| Расчёты и алгоритмы | 60 |
| UI, навигация и CRUD | 44 |
| Аудит и UX | 41 |

Исправлен воспроизводимый периодический TclError при загрузке PNG через file
в последовательных тестовых окнах на Tk 9.0.4. Ресурсы читаются Python как байты
и передаются PhotoImage с явным format="png"; отсутствующие файлы не скрываются.
Добавлены tests/test_resource_loading.py. После исправления выполнены 15 повторных
прогонов UX и загрузки ресурсов: 17 тестов в каждом, все прошли.

Сценарии нагрузки: 1000 расчётов подряд, 10 000 партнёров в списке,
20 циклов поиска, 100 повторных попыток открыть окно/обновить список
во время незавершённого запроса. Проверяется корректность и отсутствие повторных
запросов; это не измерение предельной производительности и не нагрузочный тест
многопользовательской СУБД.

Полный прогон выполнен на отдельном сервере 127.0.0.1:55439.
Данные рабочего сервера пользователя не изменялись.
